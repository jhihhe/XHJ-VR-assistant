# 售房全景上传

作者：@Jhih he

适用版本：脚本6.3.8，全景模块0.3.0。

1. 在象视“全景管理 → 售房全景”展开“上传售房全景”，选择每日VR文件夹。浏览器需要手动选择，默认目录提示按上海日期更新为 `yyyyVR/mm月/mmdd`。
2. 仅解析含完整HS编号的房源文件夹。名称最后一项为东/南/西/北；根目录JPG是一层，`2`子目录JPG是二层。图片须2:1且单张不超过50MB。
3. 勾选并查询订单。所有订单先查当前工号、不指定摄影师；未找到时再跨摄影师查找。可从“跨摄影师首查”人名列表选定优先的人；“自动”在跨摄影师阶段优先上次匹配。界面显示当前人名、范围、排队及整批进度。
4. 设置同时房源1–5套（默认1）及图片并发4/8/12/16/20（默认20）。此房源数量仅限制图片上传；一套图片传完即释放名额，坐标处理独立并行、不限制同时房源数。图片上限由所有房源共享，选择多套不会倍增图片并发。
5. 点击“开始上传”。新单直接上传；已同步订单先确认重拍会下架原全景和户型图，转换成功后再上传。一层全部完成后开始二层。
6. 图片上传关联后回读核对，随后独立执行批量获取坐标；请求超时或仍有缺失时，按缺失图片逐张补取并回读，继续重试直到全部齐全。界面显示房间、轮次和完成数量，可点击“停止坐标补取”；已传图片保留，再次开始可继续补取。成功显示“图片及坐标已就绪 · 朝向未提交”。此时尚未通过该按钮派单。
7. 核对后勾选并点击“保存所选朝向”。这一步会按文件夹朝向及制作户型图选项提交，分配设计师。提交前再次检查图片和全部坐标，提交后核实操作详情新增保存记录。

## 异常与接续

- 点击状态文字查看详情；查询、上传、坐标和保存按阶段报告。
- 网络失败停止排队；正在执行的图片任务收尾并保存已确认记录。重新选择原目录可接续本端已确认图片。
- 未经本端核对的旧图片、同日重复编号、文件内容变化、数量或楼层不符时停止，避免同名图片被错误跳过或覆盖。
- 保存请求发出前记录尝试标记。结果不明时先打开订单检查，不自动重发保存，避免重复派单。
- 核对记录按浏览器和客户端分别保存；不要随意换端重复上传。平台会话可能因登录另一端而失效。
- 三个油叉脚本功能一致，选择一个启用，避免重复注入。

## 已验证范围

真实平台验证包括浏览器双层11张、Mac13张新上传及19张接续、脚本重拍原5张到新6张，以及获授权的一单13张全部坐标及新增保存记录。Mac整链模拟覆盖重拍、双层、坐标缺失阻止保存和禁止重复保存，最终28项测试通过。JS覆盖分层、接续、文件变化、失败停止、当前工号优先及跨摄影师回退，原房堪相关回归通过。

同时两套共享图片峰值20通过离线测试；没有据此宣称服务器负载上限，也没有为覆盖组合额外修改真实订单。
